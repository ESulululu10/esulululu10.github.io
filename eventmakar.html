EventMakAR

A browser-based authoring tool for AR stories performed by physical robots — built so that a student with no programming background can write one, and run it, in a single workshop session.

Status
Deployed at a public workshop; no formal study
Role
Designed and built the authoring tool; ran it live with participants
Where
PLAYLab, University of Michigan–Flint
Code
github.com/ESulululu10/EventMakAR

The problem

An AR experience driven by real robots normally has a programmer somewhere in the loop: someone has to describe, in code or in a config file, which character does what and when. That puts the interesting authoring decisions — the story ones — in the hands of whoever can edit the project, not whoever has the idea.

EventMakAR removes that step. The author works in a browser, arranges what each of five robot characters does, and the tool emits the file the runtime already knows how to read.

How it works

  • A standalone single-file HTML/React application — no install, no build step, no server. It runs from a file on a laptop in a workshop room, which is the environment it had to survive.
  • Five robot characters, each with its own device-specific action list, so the author picks from what that character can actually do rather than from a generic menu.
  • The export is an events file in the precise JSON structure the Unity runtime’s existing parser reads, so authored stories run on the deployed AR system without anyone touching the Unity project.

Deployment

EventMakAR was used live at the Super Friday workshop at UM–Flint, where student participants authored their own AR stories and ran them with physical robots. That was the first time this authoring model met users outside the lab, and it is the reason the current thesis work assumes authoring has to survive a novice, a time limit and a room full of people.

What this is and is not. This was a deployment, not a study: I did not collect measures from the workshop. Its value here is as evidence that the authoring model works in the wild and that I can ship a system other people use — the evaluated version of this question is my current thesis work.
